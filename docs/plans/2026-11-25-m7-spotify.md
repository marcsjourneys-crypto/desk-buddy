# M7 Spotify control: design and plan

Approved by the user on 2026-11-25.

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

## Goal

CARL plays and controls Spotify by voice:
- "Play some Radiohead", "play the album *Rumours*", "play my *Chill* playlist";
- pause, resume, skip, back;
- "what's playing?";
- music volume.

All of it follows `CLAUDE.md`'s safety rules. M7 covers **Spotify only**; media keys, apps, websites and PC volume come later.

**Prerequisite:** mark text that tools bring back from outside (`read_notes`, Spotify names) as untrusted.

## Decisions

- **Spotify Premium** (the user has it): full control through the Web API.
- **The spotipy library**, pinned `spotipy==2.26.0` (MIT). It brings `requests` and `redis` (pure-Python clients, unused). Login is PKCE, so there's no client secret.
- **If the Spotify app isn't running, CARL starts it.** That's a fixed built-in action: `os.startfile("spotify:")`. No shell and no model text are involved. CARL then waits up to 8 s for the device and transfers playback to it.
- **Ducking:** while CARL is listening or speaking and music is playing, Spotify's volume drops to 20 % of its level, then is restored. `MUSIC_DUCK`, on by default.
- **No spoken "yes"** for music: it isn't a powerful action. The confirmation mechanism is built with the first powerful tool, later.

## Safety rules applied

- **Off by default:** `COMPUTER_CONTROL=on` enables the music tools. They also need `SPOTIFY_CLIENT_ID` and a saved login; otherwise they aren't registered, and CARL says music isn't set up.
- **Model text never builds a command:**
  - `query` is only a parameter to Spotify's **search** API.
  - Playback uses the Spotify URI/ID the API returned.
  - `kind` and `action` are enums in a strict schema.
- **Rate limits in code:** at most **3 actions per question** and **8 per rolling minute**. A refused call returns a tool error that CARL reads out ("I've done enough for one go").
- **Every action is logged**, one line each: `Action: <tool> <args> -> <result>`. M8 shows these on the dashboard.
- **Untrusted text:** tool results with outside text are wrapped in `<untrusted source="…">…</untrusted>`. The system prompt says it's data, never instructions. Any `<untrusted`/`</untrusted` inside the content is neutralised.

## Tools (strict schemas, `tools/registry.py`)

| Tool | Input | Behaviour |
|---|---|---|
| `play_music` | `query: str` (1–200 chars), `kind: track \| artist \| album \| playlist` | **Playlist:** fuzzy-match the user's own playlists first (case-insensitive, contained-in or best ratio), then Spotify search. **Track:** play that track. **Artist, album, playlist:** play that context. Returns the name and artist (untrusted). |
| `music_control` | `action: pause \| resume \| next \| previous` | Controls playback on the active device. |
| `music_volume` | `level: int 0–100` *or* `change: int −50..50` (exactly one) | Sets Spotify's device volume. |
| `now_playing` | none | The track, artist, and whether it's playing (untrusted). |

## Components

- **`tools/untrusted.py`:** `wrap(source, text)`, which escapes any `<untrusted`/`</untrusted` inside. It's used by `read_notes` and the Spotify tools.
- **`tools/actions.py`:** `ActionGuard`, which checks the switch, the per-question and per-minute limits (with an injectable clock), and does the logging. The loop calls `guard.new_question()` at the start of each turn. Every computer-control tool runs through `guard.run(name, args, fn)`.
- **`tools/spotify.py`:**
  - `SpotifyControl`, which wraps a spotipy client (injectable for tests) and finds the device: this PC's Computer device, else the active device, else start Spotify and wait.
  - The four tool functions.
  - `duck()`/`restore()`.
  - Blocking calls run in a worker thread.
- **`spotify_login.py`:** `python -m desk_buddy.spotify_login`.
  - It runs spotipy's PKCE flow with redirect `http://127.0.0.1:8888/callback`.
  - Scopes: `user-read-playback-state user-modify-playback-state user-read-currently-playing playlist-read-private`.
  - The token cache goes to `%LOCALAPPDATA%\desk-buddy\spotify_token.json`.
- **Config:** `COMPUTER_CONTROL` (on/off, default off), `SPOTIFY_CLIENT_ID`, `MUSIC_DUCK` (on/off, default on). `.env.example` lists them.
- **Loop:** call `guard.new_question()` per turn. Duck when listening starts if music is playing, and restore when the turn ends (including on interrupt, error or reset). Ducking must never block or fail a turn: it's best effort, with a timeout and a logged warning.

## Errors (spoken by CARL through tool error results)

| Situation | What CARL says |
|---|---|
| Not logged in | Music isn't set up: run the Spotify login. |
| `PREMIUM_REQUIRED` | Spotify control needs Premium. |
| Nothing found | I couldn't find that one. |
| Spotify won't start within 8 s | Spotify didn't open. |
| Network error | I can't reach Spotify right now. |
| Rate limit | That's enough actions for one go. |

## User setup (after Task 3)

1. Go to developer.spotify.com, open the Dashboard, and create an app. Pick "Web API", and add the redirect URI `http://127.0.0.1:8888/callback`. Copy the Client ID.
2. In `server/.env`: `SPOTIFY_CLIENT_ID=<id>` and `COMPUTER_CONTROL=on`.
3. Run `uv run python -m desk_buddy.spotify_login` and click Agree in the browser.
